F06 · Design before implementation · 4 November 2026

Catch up on what was actually taught.

A reviewed pack for one learner's recorded absence, with exact source revisions.

Four protected operator actions

  1. create_catchup_pack: attendanceId, attendanceVersion, lessons (1–20 lessonId/version pairs), homework (0–20 homeworkId/version pairs), and guidance. One pack per attendance record; create revision 1 in draft state.
  2. revise_catchup_pack: packId, expectedVersion and the same source fields except attendanceId, which cannot change. Append a revision, preserve prior content and decisions, and return to draft. Allowed from draft, approved or changes_requested; identical normalized content is rejected.
  3. review_catchup_pack: packId, expectedVersion, teachingAssignmentId, decision (approved or changes_requested), and feedback. Only a draft can be reviewed. Revalidate source versions/status and active reviewer eligibility; append the decision. A changed reviewed pack requires a new revision and review.
  4. cancel_catchup_pack: packId and expectedVersion. Terminal; retains all revisions/reviews. Cancellation remains possible if the attendance was corrected to present or a source was cancelled, while the academic year is active.

All actions require tenantId, requestId, operatorRef and reason. Guidance and feedback are nonempty normalized text of at most 4000 characters. Normalize and sort source IDs; reject duplicates and unknown fields. Exact retries return the original metadata receipt.

Source eligibility

The attendance must be absent or excused, and the year active. Every selected lesson must currently match its expected version, original attendance section/year and attendance date. Selection is explicit: an omitted lesson is not automatically considered covered. Missing attendance does not imply absence. Later learner transfers, withdrawal or inactivity do not erase the original missed-day context.

Optional homework must be published at the supplied version, belong to a selected lesson and include this enrollment in its immutable audience. Homework may retain an older lesson revision; its own retained homework version preserves that distinction instead of silently rebasing it. Packs neither assign new homework nor change homework submission/completion state.

Review requires active staff and an active teaching assignment in the original attendance section/year. Recheck attendance, lesson and homework versions immediately before review under the shared school lock. Corrections require an explicit revision/review; historical approval is not approval of later source revisions. Future parent-facing delivery must revalidate live sources and verified guardian access; this phase implements neither a portal nor automatic delivery.

Seven private tables in migration 0012

  • learning.catchup_packs: one attendance-linked aggregate, original enrollment/year/section, current revision/review, state and optimistic version.
  • learning.catchup_revisions: append-only guidance and content digest, attendance event version.
  • learning.catchup_lessons: selected lesson versions per revision; composite references enforce original section/year and retained event.
  • learning.catchup_homework: selected homework versions per revision, selected lesson link and captured-audience enrollment.
  • learning.catchup_reviews: one immutable decision per revision with feedback and teacher/staff/assignment version.
  • learning.catchup_events: action, before/after metadata, operator/reason and aggregate version.
  • learning.catchup_commands: normalized digest and original metadata result for retries.

All tables force tenant RLS and deny runtime/dispatcher access. Same-school composite references retain source history and prevent cross-pack/revision/reviewer pointers. Aggregate current revision/review references are deferred within the transaction.

Transactions and boundaries

Use the exact operator database role, a request advisory lock and the shared school row lock. The revision, references, review, aggregate update, event, security audit and command receipt commit together. Suspended/closed schools and closed years reject new changes; exact retries survive closure. Receipts/events omit guidance, feedback and lesson/homework text. The protected CLI accepts only bounded private regular JSON files.

Approval means a teacher reviewed the pinned pack, not that the learner finished it. Message reads never complete learning. F02 identity binding remains deferred; an operator label does not prove a teacher's authenticated identity. No AI generation, file retrieval, notification or HTTP route is added. Swagger remains a catalogue of implemented HTTP endpoints.

Verification gates

Test source/date/section/audience eligibility, exact retries, optimistic races, revision/review history, stale attendance/lesson/homework, cancellation, original placement after transfer, active reviewers, rollback after late audit failure, composite references, forced RLS/role denial and protected CLI. Run targeted tests, one full local suite and GitHub's fresh-database gate. Implementation evidence follows after verification.
