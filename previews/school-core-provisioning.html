Merged core result

A protected operator command creates a school business profile, audit event, outbox seed and replay result in one PostgreSQL transaction. Twenty real-database checks pass locally and on a fresh isolated database. Identity extraction has its own merged PR and 30 passing local/fresh checks. GitHub CI passed for core and identity.

Profiles remain provisioning with identity/engagement pending. There is no owner activation, website publication, consumer dispatch or anonymous school-write API in this slice.

Command flow

  1. Validate a private JSON command: request UUID, optional reserved external tenant UUID, normalized school code/name and operator audit label. Reject unexpected identity/password/contact fields.
  2. Verify the migration/operator database role on the transaction's connection.
  3. Acquire a transaction advisory lock for the request UUID. Replay an identical normalized command; reject a changed payload.
  4. Insert the pending business profile under transaction-local tenant context.
  5. Insert one versioned engagement seed, one audit event and the global operator replay result.
  6. Commit all changes together. Any constraint/downstream write failure rolls everything back.

The audit label is operator supplied; the database role is recorded separately. The CLI does not impersonate an authenticated platform-support user.

Four application tables

control.school_profiles

External/reserved tenant UUID, unique normalized school code, name, business status, identity link state, India timezone and timestamps. Forced RLS. Active status requires linked identity.

control.provisioning_requests

Unique request UUID, canonical SHA-256 input digest, profile reference, operator/database role and original JSON result. Privileged operator ledger; runtime has no table grants.

ops.security_events

Scoped append-only evidence. External actor ID/reference carries no FK into another service's user table. Runtime cannot edit/delete history.

ops.outbox_events

Scoped event ID/type, explicit versioned profile payload and timestamps. Runtime append/read only. The delivery timestamp remains null until a future reviewed dispatcher succeeds.

Event school.profile_provisioned.v1 contains only schema version, event ID, tenant ID, code/name and pending identity state. Engagement must validate and consume it idempotently before it can create a private draft; the event itself is never a publish operation.
