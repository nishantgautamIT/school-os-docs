Scope and service boundary

campus-core-api owns lesson records, homework content, audience snapshots and correction history. This phase uses the existing restricted operator command boundary. Teacher-account authentication, parent access, submissions, completion evidence, catch-up packs, AI and notifications remain future work. A recorded operator label is not proof of the teacher's identity. Publishing here changes internal durable state; it does not send a message.

The Swagger catalogue continues to list only implemented HTTP endpoints. This workflow does not expose new REST routes while F02 identity/resource authorization is deferred.

Commands and transitions

  1. record_lesson: active teaching assignment, active staff and active academic year; explicit lessonDate must be today in Asia/Kolkata and inside the year. Capture the assignment/staff/year/section and assignment version. Subject is a bounded label until a subject catalogue exists.
  2. correct_lesson: lesson ID and expectedVersion; amend subject/title/summary with a mandatory reason. Keep date, teacher and placement immutable. Historical corrections remain possible after assignment deactivation while the academic year is active.
  3. create_homework: lesson ID and current lessonVersion, title/instructions/dueDate. Create a draft pinned to that lesson revision. Due date must be today or later and inside the academic year.
  4. revise_homework: draft only, expectedVersion and explicit current lessonVersion. This also permits consciously rebasing a draft after the lesson has been corrected.
  5. publish_homework: draft only, expectedVersion and expectedAudienceCount between 1 and 200. Require the pinned lesson version still current. Snapshot every currently active enrollment with a registered student in the recorded section. Reject empty, oversized or changed-count audiences. No silent truncation.
  6. correct_homework: published only, expectedVersion; amend title/instructions with a reason. Preserve due date, pinned lesson revision and the original audience.
  7. cancel_homework: draft or published, expectedVersion. Cancellation is terminal and preserves content/source/audience history.

Each command includes tenantId, requestId, operatorRef and reason. A normalized identical retry returns its original redacted receipt; reusing the UUID with different content conflicts. No-op content corrections are rejected.

Five tables in migration 0010

  • learning.lessons: immutable school/year/section/assignment/staff/date identity plus versioned subject/title/summary. Composite assignment foreign keys ensure the exact teacher/section/year belongs together.
  • learning.homework: immutable lesson/year/section identity, pinned lesson version, draft/published/cancelled state, due date, content, audience count and version. Composite foreign keys bind homework to the lesson's scope and a retained lesson event version.
  • learning.audience: homework/enrollment/student/year/original section and captured enrollment version. Transfers and withdrawals do not rewrite the published audience.
  • learning.events: before/after content snapshots, target version, actor, database role, request and reason. Exactly one lesson/homework target per event. Full private content history is retained so later catch-up work can reference a real revision.
  • learning.commands: normalized hash and original metadata-only receipt. CLI output and receipts omit subject, title, summary, instructions and audience identities.

All five tables force tenant RLS, including for the owner. Runtime and dispatcher receive no new grants. No cross-service SQL or identity-table foreign keys. Existing applied migrations remain unchanged.

Concurrency and privacy

Acquire the request advisory lock, then the same school row lock used by provisioning, academics, people and attendance. Evaluate the India wall-clock date after acquiring that lock. State validation, audience capture, history, security audit and retry receipt commit in one transaction. Concurrent transfers, year closure and corrections serialize against publication.

Titles are at most 200 characters, subject 100, summary/instructions 4000; normalized text allows line breaks only where appropriate. Read the command from a private regular file with no symlink following, bounded at 64 KiB. Use a one-connection operator pool and bounded database statements. These safeguards do not make the content suitable for public exposure.
