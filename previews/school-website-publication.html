campus-engagement-api owns the website, publication history and approved public projection. Core owns the school profile; identity owns users/memberships. Common HTTP limits remain at the gateway.

Implementation scope

Consume the versioned core profile event through a protected operator command, create a structured private draft once, save with expected version, publish five text-first pages, roll back to an own-school historical revision and unpublish. Public GET routes read only the current published projection. No HTTP editing, private inbox, enquiry form, remote images, message sends or service-to-service auth are enabled in this slice.

Core PR#3 is merged. Identity PR#1 is merged. Operator publication approves only public content; it neither activates a core tenant nor grants private portal access. Automatic business/identity lifecycle synchronization is integration work, and no production deployment is included.

Renderer decision recorded before implementation

Use the existing Node24/NestJS/Fastify/PostgreSQL stack and Handlebars4.7.10 (lockfile pinned) for a fixed trusted text template. Double-brace values are escaped; never accept user template source, triple-brace user data or SafeString values. Compile only the checked-in template. Handlebars security guidance.

Private tables and public projection

Private tenant-scoped tables: sites, drafts, revisions and publication events, with forced RLS/same-tenant keys. Operator-only event inbox and command ledger provide request/payload deduplication. Public pages contain only approved rendered HTML, slug/page and revision identifiers; the API runtime has read-only access to that projection and no private-table grants.

Transaction rules

  • Lock request and site state; replay the original result or reject a changed payload.
  • Reject unknown/secret fields and preserve event IDs/versions from the core contract. A new duplicate event must not overwrite an existing user-edited draft.
  • Draft saves require the current expected version.
  • Validate/render the complete fixed five-page snapshot before inserting a revision and atomically replacing public pages/current pointer/history.
  • Rollback accepts only an approved revision in the same school, checks the expected current pointer and verifies a canonical SHA-256 snapshot hash. This detects changed historical artifacts, not a privileged administrator who can replace both data and hash.
  • Unpublish deletes the live projection atomically. GET checks the live table with no-store; private drafts and old revisions remain inaccessible.

Initial public content

Home, About, Academics, Events and Contact. Explicitly selected school name, descriptions and office contacts only. Text-first; no uploads, external URL fetches, student data, galleries, owner setup contacts or arbitrary HTML/CSS/JS. Canonical URLs use configured origin rather than Host headers. Responses use no-store, restrictive CSP, nosniff and frame restrictions.

Verification gates

Real PostgreSQL tests for import replay/conflict/concurrency, private runtime denial, draft/public separation, expected-version races, publish failure rollback, own-school rollback, unpublish404, stored XSS escaping, event/command input bounds and operator role/CLI enforcement. Fresh migration/rerun/failed-DDL checks and GitHub CI before review. Independent engagement database/volume at55435; no core/identity database credentials enter this service.
