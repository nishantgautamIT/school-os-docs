Implemented path

Anonymous client→Gateway + budgets→Signed private receiver→Private PostgreSQL inbox

The gateway owns exact public routing, Origin checks, body/deadline bounds and common traffic budgets. Engagement owns contact validation, the published school lookup, tenant transaction, replay receipt and operator inbox. There is no cross-service SQL or enquiry database credential in gateway runtime.

Public request contract

POST /schools/:slug/enquiries
Origin: <configured PUBLIC_ORIGIN>
Content-Type: application/json
Idempotency-Key: <UUID reused for the same input>

All four enquiry settings must be configured together. With none set, the route returns503. A partial, unsafe or directly self-referencing configuration fails at startup. Origins are exact HTTPS origins; loopback HTTP is development-only.

  • Canonical lowercase school path; no query, encoded path, redirect or alternate method.
  • At most8KiB raw JSON; absolute3-second upload deadline including chunked requests. Compressed request bodies are rejected.
  • Exact configured Origin is mandatory. This constrains browser requests; it does not authenticate a person or prevent a non-browser client from supplying that header.
  • Engagement validates contactName, Indian mobile phone, optional email/interest/message, explicit contactConsent and adult declaration. It rejects unknown fields. Declarations are not identity or age verification.
  • No browser form is included. Published page CSP is unchanged; this is the submission API and operator workflow.

Single owner for traffic limits

Every submission first passes existing general request budgets. A second policy instance uses the same gateway limiter implementation for stricter submission budgets:

  • Global: burst60, refill1 request/second.
  • Socket-derived client network: burst5, refill1/minute.
  • School slug: burst30, refill0.1/second.
  • Client-network/school pair: burst3, refill1 per300seconds.

These are continuously refilled token buckets. Retries consume the budgets too. IPv4-mapped clients normalize to IPv4 and IPv6 shares a /64; forwarding, role, user and tenant headers cannot reset identities. Rejections return429 with Retry-After. Each policy instance retains at most20000 keyed buckets and rejects new identities with503 when full; active budgets are never evicted. Submission idle expiry is900seconds, sufficient for its slowest full refill. No generic counters are copied into domain services.

Authenticated forwarding and bounded responses

The gateway generates dedicated HMAC-SHA256 headers for POST /internal/enquiries/:slug on the fixed receiver origin. The signature binds protocol purpose, epoch timestamp, method, internal path, UUID and exact raw body bytes. A frozen UTF-8 vector checks interoperability. Core-event signing credentials are separate.

Browser cookies, bearer tokens, Host spoofing, user/tenant/role headers and supplied signatures are never forwarded. A shared limit of16 active requests includes uploads and forwarding;128 downstream sockets and a3-second upstream deadline bound resources. Disconnected uploads release their slot promptly and disconnected clients cancel forwarding.

Only an exact202 receipt with accepted:true and the matching requestId is returned, within a1KiB JSON acknowledgement limit. Known errors become canned responses; unexpected, malformed, compressed or oversized acknowledgements become502 and deadline failure504. Receiver bodies, contact details, cookies, redirects and auth headers are not reflected. All responses use no-store and gateway security headers.

The gateway performs no automatic retry. After an uncertain result, retry the same input with the same UUID and respect Retry-After. Engagement atomically deduplicates committed submissions. A reused UUID with changed input conflicts409. A new enquiry requires a published contact projection; an existing accepted receipt can replay after unpublication.

Local setup and operating scope

# Engagement clone: build, db:up and db:migrate first.
# Gateway clone:
npm run build
npm run enquiries:configure-local -- ../campus-engagement-api
# Engagement clone, separate terminal:
npm run enquiries:receive
# Gateway clone:
npm start

The local helper writes only ignored regular0600 gateway and receiver env files. It creates a dedicated random key or preserves a matching existing key; mismatches, partial credentials, duplicate settings, symlinks, exposed permissions and remote databases are rejected. No secret is printed. It does not migrate a database or rotate keys automatically. An interrupted two-file write can be completed by rerunning with the preserved key.

Exactly one gateway process is supported. Restart resets in-memory counters; Redis/shared atomic counters are required before multiple replicas. Trusted-proxy extraction and fullF03 traffic/telemetry remain deferred. F02 product identity integration is deferred; private business endpoints remain closed.
