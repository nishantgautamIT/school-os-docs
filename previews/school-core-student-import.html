Protected operator import for new school-owned students, with optional draft annual placements. Reuse the existing student/enrollment rules; preserve all-or-nothing acceptance.

Contract and bounds

A private regular0600 JSON file, maximum256KiB, contains tenantId, requestId, operatorRef, reason and1–200 rows. Each row has admissionNumber and legalName, plus optional enrollment containing academicYearId, sectionId and explicit nullable rollNumber. Unknown fields, identity/contact data, invalid labels/UUIDs and malformed rows reject. This imports new students only; duplicate admission numbers never overwrite or merge children. CSV/XLSX parsing, updates, guardian/staff records and public upload routes remain future work.

Preview then accept

  1. Normalize rows using the existing student command validator. Require the operator database role and scope the transaction to the selected school.
  2. Lock the school, detect normalized admission/section-roll duplicates within the file, and simulate registrations/plans using the shared domain code inside savepoints. Return row indexes and safe error codes; never echo names/admissions. Roll back every simulated domain write.
  3. For a valid preview only, persist a school/request-scoped hash receipt, row counts, operator evidence and a30-minute expiration. Store no row payload or name/admission copies. This is the one new private table: people.student_import_batches, with forced RLS and no runtime/dispatcher grants.
  4. Acceptance requires the preview confirmation hash and unchanged normalized file/request. The hash binds the reviewed input; it is neither a credential nor human identity proof. Expired previews require another preview.
  5. Revalidate every row under the same school lock used by individual planning and academic edits. Any conflict, capacity/state change or persistence failure rolls back the entire batch. No partial acceptance or overwrite.
  6. Commit new students, optional annual plans/history, batch audit and redacted result IDs atomically. An exact accepted retry returns the original IDs, even after expiry/later edits; changed input conflicts. Concurrent accepts commit once.

Privacy and ownership

Legal names/admission numbers live on the protected student records after acceptance. Preview leaves no committed student or enrollment-history rows. The import receipt stores hashes/counts/result IDs, not source rows. IDs, reasons and planning metadata remain private; operators must not put personal data into labels or reasons. Operator credentials and supplied labels do not establish authenticated school-admin/guardian/teacher rights. No cross-service database access or HTTP student routes are added.

Verification

Test preview non-persistence, normalized duplicates, existing admissions, wrong-school/year references, capacity/roll races, optional placement, stale/expired preview, changed input, same-key concurrent acceptance, mid-batch/history/audit/receipt failure rollback, replay, forced RLS/role denial, bounded private CLI files and absent HTTP routes. Run the complete suite and fresh migration harness once the feature is ready, then matching-head GitHub CI.
