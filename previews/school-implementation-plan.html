Scope stays with its service

Core owns school/people/academic workflows; operations owns finance/resources; engagement owns websites/enquiries/messages; identity owns users/memberships/auth. Each service enforces access to its own records. Common HTTP request limiting is implemented once at the gateway when that component is built. No public bypass or unauthenticated private/admin data APIs are enabled.

Executable schema

Core has four active application tables plus the ledger after its guarded empty-database extraction migration. Identity retains its auth history plus a new identity-directory permission migration. Each uses a separate local database; the old F02 database is untouched. See core schema and verification and service ownership. The233-table catalogue remains a design roadmap.

Run the project

Prerequisites: Docker with Compose, Node 24 and npm. Clone campus-core-api and run these from its repository root. Docker binds the database to 127.0.0.1:55433. The API defaults to 127.0.0.1:3000.

npm ci
npm run db:up
npm run db:migrate
npm run check
npm run test:fresh
node --env-file=.env.core.runtime dist/src/main.js

Then open http://127.0.0.1:3000/health/ready. npm run db:down stops containers and retains the named database volume. Never run development fixtures or bootstrap scripts against production. Existing volumes retain their original credentials; changing .env does not rotate database passwords.

Working rules

  • Small feature branches and pull requests; no direct default-branch publication.
  • Every module brings its own reviewed migration, action/resource permissions and isolation tests.
  • Forward-only migrations: an applied checksum must never change. Use a new migration for corrections.
  • One transaction, one checked-out connection and transaction-local tenant context. No browser-supplied tenant is trusted on its own.
  • Rate counters, raw traffic and request logs do not become high-volume primary-database writes.
  • Keep all new design deliverables as HTML. Commit lockfiles and placeholder .env.example; never commit credentials or real school data.

Delivery backlog

Dependencies express build order, not dates. Done means merged. F04 is next; F02 and F03 are deferred. In progress includes design or review and does not claim a production release.
