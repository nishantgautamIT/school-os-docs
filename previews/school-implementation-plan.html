Authentication boundary

The merged foundation has no login API. The F02 feature branch adds narrow database functions owned by a dedicated non-login role; the API still has no direct access to global users, credentials or sessions. The server validates and locks current authorization state before selecting tenant context on the same connection. Teacher/class and guardian/child resource scopes belong to later domain milestones.

What is actually migrated?

F01 creates 11 application tables: control.tenants; iam.users, password_credentials, memberships, school_login_identifiers, permissions, roles, role_permissions, membership_role_assignments, sessions; and ops.security_events, plus the migration ledger.

F02 adds owner contacts, purpose-bound action tokens, school-scoped session fields and reviewed authentication functions. These additions are in progress and are not part of the merged F01 baseline. See the backend migrations for the executable schema; the broader catalogue remains a design draft.

Run the project

Prerequisites: Docker with Compose, Node 24 and npm. Clone campus-core-api and run these from its repository root. Docker binds the database to 127.0.0.1:55432. The API defaults to 127.0.0.1:3000.

npm ci
npm run db:up
npm run db:migrate
npm run check
npm run test:fresh
node --env-file=.env.runtime dist/src/main.js

Then open http://127.0.0.1:3000/health/ready. npm run db:down stops containers and retains the named database volume. Never run development fixtures or bootstrap scripts against production. Existing volumes retain their original credentials; changing .env does not rotate database passwords.

Working rules

  • Small feature branches and pull requests; no direct default-branch publication.
  • Every module brings its own reviewed migration, action/resource permissions and isolation tests.
  • Forward-only migrations: an applied checksum must never change. Use a new migration for corrections.
  • One transaction, one checked-out connection and transaction-local tenant context. No browser-supplied tenant is trusted on its own.
  • Rate counters, raw traffic and request logs do not become high-volume primary-database writes.
  • Keep all new design deliverables as HTML. Commit lockfiles and placeholder .env.example; never commit credentials or real school data.
